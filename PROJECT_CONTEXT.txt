ORGAPP — CONTEXTO COMPLETO DO PROJETO
======================================

Objetivo deste arquivo
----------------------
Este arquivo foi criado para ser lido por outra ferramenta de assistência de desenvolvimento. Ele descreve o propósito, a arquitetura, os módulos, as tecnologias, os fluxos, as decisões de UI/UX, os comandos, os pontos de atenção e o roadmap do projeto.

O conteúdo deve ser mantido atualizado quando houver mudanças estruturais importantes.


1. VISÃO GERAL
==============

Nome atual do produto: OrgApp / Schedule
Tipo: organizador pessoal inteligente, com arquitetura full-stack.

O OrgApp propõe unificar em uma única aplicação as principais áreas da vida do usuário:

- tarefas;
- notas;
- hábitos;
- metas;
- estudos;
- domínios/categorias;
- gamificação;
- analytics/dashboard;
- assistente de inteligência artificial.

O produto deve ajudar o usuário a transformar intenção em ação. O dashboard não deve apenas mostrar números: deve responder o que precisa de atenção, o que está evoluindo e qual deve ser o próximo passo.

Públicos previstos:

- estudantes;
- profissionais;
- concurseiros;
- pessoas que desejam organizar rotina e projetos pessoais;
- pessoas acompanhando saúde, hábitos e metas;
- leitores e usuários com objetivos de longo prazo.

O produto é pensado como uma aplicação SaaS de uso recorrente, com autenticação, persistência, experiência responsiva e possibilidade de deploy independente do frontend e backend.


2. PRINCÍPIOS DO PRODUTO
========================

- Organização pessoal em um único lugar.
- Ação antes de excesso de informação.
- Dashboard orientado a decisões.
- Analytics com propósito, não gráficos decorativos.
- Experiência rápida, clara e responsiva.
- Acessibilidade e contraste como requisitos, não como etapa opcional.
- Componentes reutilizáveis e tokens semânticos.
- Alterações graduais, pequenas e verificáveis.
- Preservação dos contratos existentes de API e do estado Redux.
- Não copiar assets, layouts ou código de terceiros.

O projeto usa como referência conceitual o repositório irmão Power-BI-Design-Files, principalmente estes princípios:

- começar pela decisão que o usuário precisa tomar;
- tornar a análise visível;
- usar interação com propósito;
- tratar hierarquia visual como parte da análise;
- construir soluções reutilizáveis;
- usar espaçamento, tipografia, cor e layout de forma intencional.

A referência é inspiração metodológica. O OrgApp deve continuar sendo uma aplicação React própria, sem importar arquivos PBIX, arquivos Figma ou visuais de terceiros.

15. DIRETRIZES DE UI/UX FUTURAS
===============================

A repaginação completa deve seguir:

Grid e espaçamento:

- base de 8px;
- permitir 4px para ajustes menores;
- preferir 8, 12, 16, 24, 32, 40 e 48px;
- evitar valores arbitrários sem justificativa.

Tipografia:

- Display para mensagens principais;
- Heading para títulos de seção;
- Body para leitura;
- Label para controles e metadados;
- Inter/system-safe como default moderno;
- line-height suficiente para leitura;
- não usar texto cinza escuro sobre fundo escuro.

Cores:

- Primary para ação principal/brand;
- Secondary/accent para apoio;
- Background/base para página;
- Surface para cards;
- Elevated para controles/elementos destacados;
- Border para separação;
- Text primary/secondary/muted;
- Success, warning e danger;
- validar combinações WCAG AA.

Componentes:

- Default;
- Hover;
- Focus-visible;
- Active;
- Disabled;
- Loading;
- Empty;
- Error.

Microinterações:

- sutis;
- rápidas;
- não bloquear tarefas;
- respeitar prefers-reduced-motion;
- evitar animação apenas decorativa em excesso.

Conversão/UX:

Apesar de ser um produto de produtividade e não uma landing page de venda direta, CTAs devem ser orientados à ação:

- Criar tarefa;
- Fazer check-in;
- Continuar estudo;
- Revisar meta;
- Abrir assistente;
- Ver detalhes.

CTAs primários devem ser visualmente claros, mas não agressivos. A ação mais importante da tela deve ter destaque único.
